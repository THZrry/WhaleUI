# 项目技术指标
**这部分内容不管你处于那个步骤都需要重点关注**，因为这是整个项目的标准。
- **技术选型**：整体使用C++14，暴露C API以支持多语言多系统的调用。禁止使用`template`, `try ... catch ...`等造成体积膨胀或性能下降的代码，标准库除外。整个项目的代码风格接近C，但允许使用`class`, `STL`等C++的工具。项目使用xmake管理，优先选择xrepo下载相关库，不要将第三方库硬编码进项目，可以使用git进行链接，并且除了include相关文件都要被gitignore包括在内。渲染使用SDL3，HTML与CSS的解析可以调用第三方库，如lexbor，不过编译选项可以关闭HTML输出等排版不需要的功能以减小体积。
- **跨平台及兼容性**：在这个项目中，Windows，Mac，Linux（Wayland优先，X11兼容）是主要的兼容平台，但Android与IOS可以预留相关实现空间。渲染库使用SDL3，通过SDL_GPU进行硬件渲染。Vulkan1.1/DirectX11/OpenGL4.6是主要兼容的底层，通过中间shader实现而不是各写一份代码。
- **风格效果**：你需要实现一套非常轻量但高性能的HTML渲染库，不过不用把HTML5/CSS3标准完全实现。你需要实现一个div并且让所有tag继承它（即使是单标签）然后针对不同的标签做适配，包括CSS和特殊功能等，以strong、input和summary举例，它们可以通过div和一些脚本实现。由于css盒子大量使用div，你需要保证每个div的占用足够小，并且在必要时，可以使用ECS架构。参照Chromium做一套风格，再参照Windows Classic，Windows7 aero，Windows10 Metro，Windows11 Fluent，gtk，MacOS，Google Material Design分别已有并验证的css翻译成本项目的css，支持主题色和深浅色，要求保留一套通用的class，并对每个Tag进行预设。应用需要支持深浅色，并默认设置与系统相对应的颜色模式和系统主题，允许用户切换。
- **项目结构**：本项目遵循生产代码的原则，不将第三方依赖完整内置，而是链接，并对必须的外部资源进行gitignore。src中按序整理文件，并将系统相关的底层单独以文件夹放置。脱离底层的方法需要提供并集中在src中。
- **性能**：这是项目的重点之一。可派V4Pro的子代理完成核心性能代码的编写。渲染层面注意脏画面、遮挡和缓存机制，以最低的开销实现相同的渲染画面。文件解析可以对大文件进行哈希缓存，底层DOM可以选择直接使用lexbor。默认支持屏幕分辨率（切换时需要检测）默认在省电模式降低至60帧，允许用户设置，支持动态刷新率。

# 第一步：搭建环境
本机已有MinGW64和git，请使用xmake和git正确配置项目以及编译选项。
渲染：SDL3, SDL_Image, SDL_Font, stb_image, stb_image_write, stb_font等，音频和视频流出位置但注释，暂不考虑。
布局：lexbor
字符：Charset等
任务：thread相关库、libco等
其他自行补充，要求C/C++14实现，最小依赖且兼顾性能与空间占用。

stb_font不支持彩色Emoji，参考 https://github.com/nothings/stb/issues/512 与 https://github.com/nothings/stb/pull/1135 的支持并作为补充在项目中实现。

Build Target比较多，包括：
- **Full**：全功能包含，使用SDL的图片字体等实现
- **Lite**：全功能的精简实现，砍掉未使用的功能，使用stb管理资源
- **Minimal**：只保留布局相关的功能，不支持HTML的解析和缓存等功能，保留stb管理资源，用于仅拿来做简单界面的极限场景

# 第三步：内部实现
这是最重要的一步，需要多个子步骤完成。

- 1. DOM功能实现：接入lexbor，完成HTML、CSS文件的读取解析、DOM的生成修改
- 2. 标签功能：由于项目是将所有tag视为div并对应特殊处理，可能需要内部表示，用于处理这个。如果有内部用于渲染的表示，为了性能，可以考虑ECS等性能优先架构。
- 3. 样式处理：为渲染做准备，处理样式
- 4. 渲染实现：经过优化的渲染实现，初步实现功能，因为HTML/CSS的标准体系过于庞大，可以参考`README-css.md`先实现部分
- 5. 流程处理：整个流程可能涉及多线程和异步等。这一步用于优化流程，打磨整个loop的逻辑
- 6. 外围功能：包括应用API和窗口API等
- 7. 样式：把Chromium，多种Windows，MacOS，Material Design等样式转换成本项目使用的样式，注意需要支持热切换。
- 8. 测试：优化修改测试，直到单元测试全部通过。
